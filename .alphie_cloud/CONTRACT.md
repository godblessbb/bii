# 你在执行一份目标合同

你在一个隔离的 git 工作区里独立完成一个开发目标。没有人在线陪你，平台只做三件事：
在你每次交回后跑验收命令、请一位独立审查员看 diff、把结果原样交还给你。

规矩：
- **「完成」由平台判定，不由你判定。** 验收命令全部退出码 0，且独立审查员认可，才算完成。你自己也要跑验收命令，但你说「过了」不算数。
- **受保护路径不得修改**，也不得新增同类文件绕过（例如新写一个测试替代被保护的测试）。平台会逐字节检查。
- **规格没写的实现选择（界面形态、默认值、布局、命名……）由你自己决定，不要停下来问。** 选一个合理的，做完，在最后回复的「决定」一节写清：选了什么、还考虑过哪些、为什么。人以后可以推翻。
- **只有这几种情况才停下来问人**：目标自相矛盾或做不到；必须修改受保护路径；需要外部资源、凭证、联网部署；会删除数据。停下时回复最后一行写 `ESCALATE: <一句话问题>`，别的情况一律不要写这一行 —— 没有要问的就整行都不要写，尤其不要写 `ESCALATE: 无`；问题有几个明确的答案可选时写在同一行：`ESCALATE: <问题> 选项：<答案一> | <答案二>`，平台会把选项做成按钮让人一键回答。
- 不要 git commit、不要 push、不要改 git 配置。平台每段结束自己存档。
- **技术问题不要问人**（变基、合并冲突、某条测试算谁的、解释器 / 验收命令路径写错）：用户不是工程师，答不了。验收里挂的测试若在主线头上本来就挂，平台会自己判给主线、不挡你；验收命令本身写错了（例如裸 `python` 找不到），在交付里写明，由平台 / AI 改。只有产品取舍（要不要做、做成什么样）才 ESCALATE。
- 最后回复用中文，四节，标题固定写成 `## 做了什么` / `## 验收怎么证明的` / `## 决定` / `## 残留风险`。
  `## 决定` 一节每条一行、以 `- ` 开头，列出到目前为止**仍然有效的全部**决定（不只是这一段新做的）：选了什么、还考虑过什么、为什么。没有就写 `- （无）`。平台会把这一节原样拿给人看，人可以逐条推翻。

## 背景
仓库是用户的个人网站 datode.com（GitHub Pages，公开仓库 godblessbb/bii）。`weibo.md` 是他微博老号的碎句合集：9 个小节（另有开头的「按」），共 107 条「- 」碎句。上一张单（ct_0d37734f）在 `_preview/weibo/` 做了第一版文艺设计稿（水彩纸/夜空、霞鹜文楷、5 幅小王子意境插画、YouTube 音乐卡片），已经公开在 datode.com/_preview/weibo/。

## 用户对第一版的意见（原话）
「排版不是很满意，排的有点满，字有点多，不够简洁，单条内容是不是可以间距大一点，加一点一以贯之的设计元素比如纸飞机或是别的，然后要根据文字内容生成一些手绘的插画元素并且就放在文字内容附近，再出一版。」

我实测的第一版问题：1440 宽时相邻两条碎句只隔 23px（比一行行高 34px 还小），每行约 38 个字；正文以外还有约 140 字的附加文字（「二〇一二至二〇二二，一个被炸掉的老号……」这句标语是上一版执行者自己编的，原文里没有，年份也没核实；还有目录、页脚说明等）。5 幅插画只是放在小节之间的大图，跟具体哪句话无关。

## 要做的：第二版设计稿，放在新目录 `_preview/weibo-v2/`
第一版 `_preview/weibo/` 一个字节都不动，留着给用户并排比较。线上页面（index.html、js/app.js、css/site.css）和 weibo.md 都不动。

1. **更疏朗、更简洁**：碎句之间留足呼吸感；行宽收窄；把页面上不是正文的文字压到最少——不要标语、不要编造的年份、不要长页脚说明（字体授权等写进 DESIGN.md，页面上不放）。小节标题是原文，可以保留，可以做成目录。「字有点多」只能靠版式解决：**weibo.md 正文一个字都不许删、不许改**（用户的长期规矩），正文仍然现读 `../../weibo.md` 渲染。
2. **一以贯之的母题**：用户举例纸飞机，也可以选别的，但要说明理由（写进 DESIGN.md 的决定里）。同一个母题贯穿全页，在至少 3 种用途里出现（比如小节标记、碎句间分隔、阅读进度/回到顶部、音乐按钮……），全部引用同一个来源（一个 `<symbol>` 或一个文件），不要每处画一个不一样的。
3. **跟着句子走的手绘插画**：从 107 条里挑画面感强的句子（例如机场出发大厅的拥抱、写在厕纸上的诗、堪察加落雪的火山……由你挑），按句子内容原创手绘风插画，**放在那条句子旁边**（侧边或紧贴着上下都行），不压到正文文字。至少 10 幅、指向 10 条不同的句子、覆盖至少 7 个小节；每幅是不同的画，统一一种笔触（比如单色墨线、轻微抖动的手绘线），是小尺寸的点缀元素而不是大图。必须原创：不临摹任何现成插画（包括《小王子》原书插图），不用「Le Petit Prince」名称，不画真实人物肖像。所有资源同源放在仓库里，不引用外链。
4. **音乐**：沿用第一版的方案和代码（YouTube 官方嵌入、第一次点页面任意处开始播放、主动暂停后不再自动唤醒、连不上时降级为链接卡片、不在仓库里放音频），但在新版式里放得更轻、不抢正文；YouTube 条款要求播放器可见（不小于 200×200）这一条照守。上一版审查员指出视频 ID `ZtDDXF_VfZE` 是凭记忆填的：请用 `https://www.youtube.com/oembed?url=https://www.youtube.com/watch?v=<id>&format=json` 实际核实它是不是 The Walters《I Love You So》，核实结果写进 DESIGN.md；核实不了就如实写「未核实」。
5. 深浅色跟随系统；手机 390 宽不横向溢出；系统开「减少动态效果」时所有动画停掉（母题若有飞行动画也要停）；整页同源资源 ≤ 3MB（可以复制第一版的字体子集文件到新目录）。
6. DESIGN.md：说清这版相对第一版改了什么、母题的选择、每幅插画对应哪句话、音乐方案（含 autoplay 与版权两个词）和视频 ID 核实结果。

## 验收（平台在本机跑，脚本你看不到，规则全文如下）
页面从仓库根起静态服务，以 `/_preview/weibo-v2/` 打开，外网请求全部拦掉。
- W1 外网全被拦时页面不报 JS 错，同源请求没有 4xx/5xx

- W4 仓库没有新增音频文件
- W5 有 `[data-music]` 播放器和 `[data-music-toggle]` 开关，外网被拦时点开关不报错
- W6 390 宽不横向溢出；2560 宽时 `[data-weibo-body]` 宽 480–900px
- W7 减少动态效果时没有正在跑的 CSS/Web 动画
- W8 深浅色页面底色亮度差 > 0.25
- W9 同源传输量 ≤ 3MB
- W10 `_preview/weibo-v2/DESIGN.md` 存在且含 autoplay、版权
- V1 weibo.md 每一条「- 」碎句渲染成一个 `[data-entry]` 元素，数量相等（107）；1440 宽时同一父元素下相邻两条 `[data-entry]` 的垂直间距（下一条上沿 − 上一条下沿）最小 ≥ 48px、中位数 ≥ 56px；390 宽时最小 ≥ 32px
- V2 1440 宽时第一个 `[data-entry]` 的宽度 ÷ 它的字号 ≤ 32（每行最多约 32 字）
- V3 可见的 `[data-illustrates="<原文片段>"]` 插画 ≥ 10 幅：属性值去空白后是 weibo.md 某一行的连续原文、≥ 6 字；指向 ≥ 10 条不同的行、覆盖 ≥ 7 个小节（「按」不算）；每幅是不同的画（不同的同源图片文件，或内容不同的内联 svg）；1440 宽时显示宽度 64–320px；与包含该片段的那个 `[data-entry]` 的矩形距离 ≤ 120px，且不比离其他任何 `[data-entry]` 更远（容差 24px）；1440 和 390 宽下插画矩形与 `[data-weibo-body]` 里正文文字的矩形重叠面积 ≤ 40px²
- V4 可见的 `[data-motif="<用途>"]` ≥ 6 个、用途值 ≥ 3 种，每个都引用同一个来源（元素本身或其内部的 `<use href="#同一个id">`，或同一个 img 文件，或同一个 CSS 背景图）
- V5 `[data-weibo-body]` 和 `[data-music]` 以外的可见文字（weibo.md 小节标题除外）合计 ≤ 30 字；`[data-weibo-body]` 里不是 weibo.md 原文的可见文字 ≤ 12 字
